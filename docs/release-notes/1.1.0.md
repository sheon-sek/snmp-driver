# SNMP Driver 1.1.0 发布说明

- **Module ID：** `com.jw.snmpdriver`
- **版本：** 1.1.0
- **平台：** Ignition 8.3（测试环境 Ignition 8.3.10）
- **升级来源：** 1.0.0

> 本 Release 只包含发布说明。模块签名与 `.modl` 附件由发布负责人人工完成并上传。

## 新增功能：Trap / Inform 接收

- 接收 SNMP v1 Trap（按 RFC 3584 转换为 v2 形式）、v2c Trap、v2c Inform、v3 Trap、v3 Inform。
- Inform 只在入队成功后 ACK；60 s 内重复的 Inform 不重复计数（`DuplicateInformCount`）。
- 按 Device Host 与 `Trap Source Allowlist`（IP/CIDR）把 Notification 归属到已配置的 Device；未匹配来源只计入 `ListenerUnmatchedCount`，多个 Device 匹配同一来源时广播。
- 同一端口上的多个 Device 共享一个 Trap Listener；端口绑定失败时只有 Trap 进入 `Degraded`，轮询不受影响，每 30 s 自动重试。
- 每 Device 节点 `[Device]/Traps/`：`Status`、`LastError`（含处置建议）、`ListenerEndpoint`、`LocalEngineId`、各类接收/丢弃计数。
- 最近一条 Notification：`Traps/Last/*` 与一致快照 `Traps/Last/Json`。
- 按 trapOID 的动态 Tag：`TRAP.Count/<oid>`、`TRAP.LastTime/<oid>`、`TRAP.LastVarbinds/<oid>`、`TRAP.Sequence/<oid>`（每 Device 最多 256 个 trapOID，无订阅时 240 个）。
- v3 Trap 需配置发送方 engineID（`Trap Sender Engine ID`）；v3 Inform 使用持久化的 Gateway 本地 engineID，Gateway 克隆或换机时自动重新生成，旧文件保留为 `.cloned-<ts>`。
- 每 Device 限速（默认 100/s，burst 2×）；队列、PDU 大小、varbind 数量均有上限。
- License 无效时端口保持打开，Trap 丢弃并计数、Inform 不 ACK；License 恢复后自动恢复。

## 修复

- 模块启动阶段 License 尚未判定时，`Status` 不再短暂显示 Unlicensed（#40）。
- v3 Notification 隐私口令错误时正确计入 `AuthFailureCount`（#41）。
- Gateway 启动后第一个 Device 上正确显示 `LocalEngineId`（#41）。
- Designer 写入 V2C Integer32 返回 `Bad_GatewayCommOff`：定位根因并补充写入/回读回归测试（#32，见测试报告）。

## 兼容性与升级

- 1.0.0 的设备配置在 1.1.0 下无需修改即可加载；新增 TRAP 字段取默认值（`trapEnabled=false`），轮询结果与升级前一致。
- 原地升级与恢复 1.0.0 时期 `.gwbk` 两种路径均已验证。
- 恢复备份、克隆 Gateway、Docker 部署（固定 hostname/MAC、UDP 162 端口映射会改写源 IP）的处置方法见 `docs/USER_MANUAL_1.1.0_CHANGES.md`。
- 不支持冗余 Gateway。

## 已知限制

- 不包含：MIB 文件导入与名称解析、逐条 Trap 事件持久化（Event Streams / SQL）、Gateway 级任意来源 Trap 接收、Walk/Table/Browse、多 varbind SET、冗余 Gateway 支持。
- Trap 语义为 Notification Snapshot（状态快照 + 计数），不是逐条事件队列。
